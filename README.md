# Wi-Fi Proxy Auto-Set (HAPP Gateway Proxy)

Скрипт для Windows, который **при каждом подключении к Wi-Fi автоматически прописывает в системных настройках прокси адрес основного шлюза и порт `10809`**.

## 🎯 Для чего это нужно

Сценарий использования — **раздача интернета с телефона через HAPP**:

1. На телефоне запущен **HAPP** (VPN-клиент, работающий как локальный прокси).
2. В настройках HAPP включена опция **«Разрешить подключения из локальной сети»** (Allow connections from LAN).
3. Телефон раздаёт Wi-Fi (точка доступа).
4. Ноутбук подключается к этой точке доступа.
5. Скрипт при подключении автоматически ставит в Windows прокси `http://<IP-шлюза>:10809`, где `<IP-шлюза>` — это адрес телефона в локальной сети (обычно `192.168.x.1`).
6. Весь трафик ноутбука (браузеры и приложения, использующие системный прокси) идёт через HAPP на телефоне.

Без этого скрипта при каждом подключении пришлось бы вручную заходить в «Параметры → Сеть и Интернет → Прокси» и вбивать IP-адрес — а он может меняться (например, `192.168.43.1` у одного телефона, `192.168.137.1` у другого, `172.20.10.1` у iPhone и т.д.). Скрипт решает эту проблему: **всегда актуальный IP шлюза — автоматически**.

Ориентирован в первую очередь на **ноутбуки**, которые подключаются к Wi-Fi, раздаваемому с телефона.

## 📋 Требования

- **Windows 10 / Windows 11** (используются `Get-NetIPConfiguration`, `Set-ItemProperty`, `Add-Type` — есть во всех современных версиях).
- **PowerShell 5.1+** (встроен в Windows 10/11).
- **Права администратора** — только на этапе создания задачи в Планировщике (для самого выполнения не нужны, если задача запускается от имени текущего пользователя).
- На телефоне: **HAPP** с включённым пунктом «Разрешить подключения из локальной сети» и прокси, слушающим порт **`10809`**.
- На телефоне: раздача Wi-Fi (точка доступа / хотспот).

> ⚠️ **Важно:** убедитесь, что в HAPP прокси реально слушает порт `10809` и разрешены входящие подключения из локальной сети. Иначе после смены настроек браузер не сможет выйти в интернет, пока вы не отключите прокси.

## 📦 Установка

### Шаг 1. Сохраните скрипт

1. Создайте папку, например `C:\Scripts\`.
2. Положите в неё файл `Set-GatewayProxy.ps1` (идёт отдельно, вместе с этим README).

### Шаг 2. Разрешите выполнение скрипта

В Планировщике задач мы будем запускать скрипт с параметром `-ExecutionPolicy Bypass`, поэтому менять политику выполнения глобально **не нужно**. Если вы хотите запускать его и вручную — можно один раз выполнить в PowerShell:

```powershell
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
```

### Шаг 3. Зарегистрируйте источник событий (необязательно, но рекомендуется)

Скрипт пишет логи в журнал Application. Если источник GatewayProxyScript не зарегистрирован, Write-EventLog вернёт ошибку (сам прокси при этом всё равно установится, но логов не будет). Чтобы логи писались корректно, выполните в PowerShell от имени администратора один раз:

```powershell
New-EventLog -LogName Application -Source "GatewayProxyScript"
```

### ⚙️ Настройка Планировщика задач

Задача должна запускаться при каждом подключении к Wi-Fi.

1. Нажмите Win + R, введите taskschd.msc, нажмите Enter.
2. В правой панели выберите «Создать задачу…» (не «Создать простую задачу»).

### Вкладка «Общие»

Имя: Wi-Fi Proxy Auto-Set

- Описание: Автоматическая установка прокси на шлюз при подключении к Wi-Fi (HAPP).
- Параметры безопасности: выберите «Выполнять только при входе пользователя в систему».
- Это принципиально: настройки прокси хранятся в HKCU — ветке реестра текущего пользователя. Задача от имени SYSTEM изменит настройки не того пользователя, и в вашей учётной записи прокси не применится.

### Вкладка «Триггеры»

- Нажмите «Создать».
- Начать задачу: «При событии».
- Выберите «Настраиваемый» → «Изменить событие…».
- Укажите:
1. Журнал: Microsoft-Windows-NetworkProfile/Operational
2. Источник: NetworkProfile
3. Код события: 10000
- Нажмите OK.

Событие 10000 в журнале NetworkProfile генерируется, когда Windows успешно подключается к сети и назначает ей профиль. Это самый универсальный триггер и для Wi-Fi, и для Ethernet.

### Вкладка «Действия»

1. Нажмите **«Создать»**.
2. **Действие:** «Запуск программы».
3. **Программа или сценарий:**
   powershell.exe

4. **Добавить аргументы:**
   -WindowStyle Hidden -ExecutionPolicy Bypass -File "C:\Scripts\Set-GatewayProxy.ps1"

> Замените `C:\Scripts\Set-GatewayProxy.ps1` на реальный путь к вашему файлу.
5. Нажмите **OK**.

### Вкладка «Условия»

- Снимите галочку **«Запускать только при питании от электросети»** — иначе на ноутбуке от батареи задача не сработает.

### Сохранение

Нажмите **OK**, введите пароль своей учётной записи (если потребуется).

Готово — теперь при каждом подключении к Wi-Fi (и при входе в систему, если сеть уже активна) прокси автоматически обновится на `IP-шлюза:10809`.

## ✅ Проверка работы

1. Подключитесь к Wi-Fi, раздаваемому с телефона.
2. Откройте **Параметры → Сеть и Интернет → Прокси**.
3. В разделе «Использовать прокси-сервер» должно быть:
- **Адрес:** IP-адрес телефона в локальной сети (например, `192.168.43.1`)
- **Порт:** `10809`
4. Проверьте свой внешний IP, например на `https://2ip.ru` — он должен отличаться от IP вашего провайдера и соответствовать выходной точке HAPP.
5. При необходимости посмотрите **«Просмотр событий» → «Журналы Windows» → «Application»** — там будут записи от источника `GatewayProxyScript`:
- `Event ID 101` — прокси успешно установлен.
- `Event ID 100` — не удалось определить шлюз.

## 🛠️ Решение проблем

| Проблема | Что проверить |
|---|---|
| Прокси не устанавливается | В Планировщике на вкладке «История» задачи есть ошибка? Убедитесь, что в аргументах правильный путь к `.ps1`. |
| Прокси установлен, но интернета нет | В HAPP включено «Разрешить подключения из локальной сети»? Прокси в HAPP слушает именно `10809`? Брандмауэр телефона не блокирует входящие? |
| При смене Wi-Fi прокси не обновляется | Триггер настроен на событие `10000` из журнала `NetworkProfile`? Проверьте, что задача включена и запускается от вашего пользователя. |
| Нужно вернуть «как было» | Откройте «Параметры → Сеть и Интернет → Прокси» и выключите прокси, либо выполните в PowerShell:<br>`Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Internet Settings" -Name ProxyEnable -Value 0` |
| Настройки не применяются сразу | Скрипт вызывает `InternetSetOption(INTERNET_OPTION_SETTINGS_CHANGED)` и `INTERNET_OPTION_REFRESH` — обычно применяется мгновенно. Если нет — перезапустите браузер: некоторые приложения кешируют настройки прокси при старте. |
| Задача не запускается при подключении к Wi-Fi | Проверьте, что в аргументах `-WindowStyle Hidden` не мешает отладке — попробуйте временно убрать его и посмотреть, открывается ли окно PowerShell. |

## 📝 Заметки

- Скрипт меняет только **пользовательский** прокси (`HKCU`), который используется в Параметрах Windows и большинством приложений (Chrome, Edge, приложения на .NET, часть Electron-приложений и т.д.). Приложения, которые ходят в сеть в обход системного прокси (например, использующие собственные настройки), скрипт не затронет.
- `ProxyOverride` исключает локальные адреса — трафик к самому шлюзу и `localhost` идёт напрямую, что удобно для отладки HAPP.
- Если у вас несколько сетевых интерфейсов (Ethernet + Wi-Fi) и активен не тот, что нужно, `Get-NetIPConfiguration` вернёт шлюз первого активного интерфейса с заданным шлюзом. При необходимости можно уточнить фильтр по `InterfaceAlias` (например, `Where-Object { $_.InterfaceAlias -like "*Wi-Fi*" }`).
